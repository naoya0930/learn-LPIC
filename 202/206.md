# システムセキュリティ

## ルータを構成する
- LPICでは基本はiptalbesの挙動
- 最近はnftablesが使われている
### バケット転送種別
- パケット転送の時にルールの適応などを実施するプロセスが存在
- ポイントによって名称が
  - この種別をデフォルトチェインと呼ぶ
  - カーネルによって定義している
- INPUT...自分宛に届いた時
- OUTPUT...そのマシン自身から送信するとき
- FORWARD...そのマシンを通過する時
- PREROUTING
  - そのマシンが書き換え予定のパケットが到達した時
- POSTROUTING
  - そのマシンが書き換えたパケットを送信する時


### パケットフィルタリングテーブル 
- iptable/nftableサービスで参照される
- どのように端末を通るかによって制御を定義する
- この制御をルールテーブルとして保存する
  - テーブルでの挙動をターゲットと呼ぶ
- テーブルの種別
  - filter...パケットを通過するか、破棄するか
    - ACCEPT...許可
    - DROP...破棄
    - REJECT...拒否通知を送って破棄
  - nat...アドレス変換
    - SNAT...送信元を書き換えてプライベートIPから外へ
    - DNAT...宛先を書き換えて内部サーバへ
    - MASQUERADE...動的なIPでのSNAT
  - mangle...QoS制御やパケットの目印付けをする
    - TOS...Type of Serviceを書き換え
    - TTL...Time to Liveの書き換え
    - MARK...パケットに目印をつける
- 他にLOGというターゲットも存在
### テーブルとテーブルが参照するチェイン
- filter...INPUT,FORWARD,OUTPUT
- nat...PREROUTING, POSTROUTING, OUTPUT
- mangle....すべてのチェイン

### パケットフィルタリングを設定 iptables
- iptables -t {テーブル名}
  - 何も指定しないとfilterが指定される
- 主要コマンド
  - iptables -A [chain] [rule]
    - チェインにルールを追加
  - iptables -D [cahin] [rule]
    - チェインからルールを削除
  - iptables -P [chain] [target]
    - ターゲットの非定義なルールの挙動を変更
  - iptables -L [chain]
    - ルールを表示
  - iptalbes -F [chain]
    - チェイン内のルールを全て削除
  - iptables -N [chain]
    - ユーザ定義チェインを作成
  - iptables -X [chain]
    - ユーザ定義チェインの削除
  - iptables -I [chain] [rule_num] [rule]
    - ルール番号を指定して挿入
- ルールの記法
  - `-s 送信元`
  - `-d 送信先`
  - `--sport 送信元ポート番号`
  - `--dport 送信先ポート番号`
  - `--to {ip:port}`
  - `-j ターゲット`
  - `-p {L4プロトコル}`...tcp/udp/icmp/all
  - `-i 入力インタフェース名` eth0など
  - `-o 出力インタフェース名`
- その他オプション
  - -v...詳細を表示
  - -n...IPやポート番号を数値で表示
  - --line-numbers...ルール番号を表示
#### コマンド例
- `iptables -P FOWARD DROP`
  - FORWARDチェインの挙動をDROPに変更
- `iptables -A INPUT -p icmp -s 192.168.120.0/24 -j REJECT`
  - 192.168.120.0/24からのICMPを拒否
- `iptables -A INPUT -p tcp --dport 23 -j LOG --log-prefix "Try port23..."`
  - 23番ポートの試行をログに残す
    - 送信先はカーネル基準
      - /etc/syslog.conf
      - /etc/rsyslog.confに従う
- `iptables -A FORWARD -d XXX.XXX.XXX.XXX -p`
- ※ これはプロキシの話ではなく、ルータの話
  - L3-L4レイヤのIP置き換え

#### v6の送受信 ip6tables

#### 経路設定
- 以下で採用プロトコルが異なる
  - 内部ゲートウェイ(IGP)
  - 外部ゲートウェイ(EGP)
- 経路交換プロトコル
  - RIP(IGP)
    - 30sごとに情報を自身の全てのルート情報を交換
    - ルータを何台通過するかで経路を評価
    - 15以上先のルータには飛べない
  - RIPv2(IGP)
    - VSLMに対応した。
    - ブロードキャストではなく、マルチキャストを実施
  - OSPF(IGP)
    - トポロジーマップの共有を実行して、最短コストを共有
  - BGP(eGP)
    - 経路に対して複雑な条件をつけられる

#### ルーティングソフトウェア
- スイッチ、ルータと会話して情報の受信、送信を実施
  - 経路設定のプロトコルによる操作を実施できる
- `Quagga`が有名

- `/proc/sys/net/ipv6/ip_fowarding`を1にする(ipv6)
- 設定を永続化するには、`/etc/sysctl.conf`,`etc/sysconfig/network`で設定

### ProFTPDを設定する
- `proftpd.conf`
- Apache httpdファイルっぽい書式
- ディレクティブ
  - 設定の単位
- ブロック
  - ディレクトリなどを限定した設定
  - <>でくくる
- コンテキスト
  - ディレクティブが使用できる場所
  - 各ディレクティブによって有効なコンテキストが存在する
#### 主要なProFTPDのブロック
- <Directory {dir}>...特定ディレクトリ
- <Anonymous>...誰でも入れる匿名ftp
- <Global>...すべての接続
- <Limit Write|Lead|ALL>
  - 指定ブロックで実行できる操作
- <Limit {commnad,commnad_group}>
  - 指定ブロックで実行できるコマンド

#### 主要なアクセス制御
- Order 
  - AllowとDenyの判断順序をチェック
  - `Allow,deny`...allowであれば、denyしない
  - `deny,allow`..denyであれば、allowしない
- Allow from {host,network}
  - 許可するホストやネットワークを指定
- AllowAll
  - そのブロック内ですべてを許可
- AllowUser {user}
- AllowGroup {group}
- Deny from {host,network}
- DenyAll
- DenyUser {user}
- DenyGroup {group}

#### Limitで指定するコマンド
- コマンド
  - RETR...サーバからクライアントファイル転送(Retrieve)
  - STOR...クライアントからサーバ転送(STORE)
  - REN...ファイル名変更
  - DELE...ファイル削除
  - RMD...ディレクトリ削除
  - SITE_CHMOD...パーミッション変更
- コマンドグループ
  - DIRS...ファイル名一覧の取得
  - READ...ファイルの読み込み
  - WRITE...ファイル、ディレクトリの作成・削除
  - ALL...すべてのFTPコマンド
  - LOGIN...ログイン

#### 主要な制御コマンド
- DeafaltRoot {dir}
  - ログインできる先を制限する
  - `~`を指定すればログインユーザのホームのみ許可

### vsftpdの設定
- `csftpd.conf`で設定する
- 設定ファイルが超簡単
- `chroot_local_user=YES`でホームディレクトリを使用するように指定

### Pure-FTPDの設定
- `pure-ftpd.conf`で設定する
- 起動時にオプションを渡して一時的に設定を当てることもできる
- pure-ftpd -4...IPv4のみ利用
- pure-ftpd -A...全ユーザに対しchroot
- pure-ftpd -B...デーモンとして動作
- pure-ftpd -c {num}
  - 最大クライアント
- pure-ftpd -C {num}
  - IPアドレスあたりの最大クライアント
- pure-ftpd -e...匿名ユーザのみログインを許可
- pure-ftpd -E...匿名ユーザは利用不可
- pure-ftpd -i...匿名ユーザにアップロードを禁止

### 汎用のFTP
#### FTPサーバのアクセス制限
- ほとんどのftpサーバはこのファイルを読みに行く
- `/etc/ftpusers`にユーザ名を書く
  - このファイルに書かれるとログインできなくなる

#### 旧式FTPの基本動作
- ポート20
  - FTPデータ転送用
  - これはサーバ側からクライアントに送信
- ポート21
  - FTP要求用
  - これはクライアントからサーバに送信
  - 開けたポート(20)も同時に教える
- 現代においてポート20はほとんど使用しない
  - 制御時に自分の開いているポートを伝える
### 新式FTPの基本動作
  - 外部からの通信を原則として受信しない
  - クライアントリクエストにして、ステートフルなFWを通過する。
  - つまりサーバにデータを送らせるのではなく、クライアントからダンロードリクエストする。
  - この方式をFTPパッシブと呼ぶ
- クライアントからのリクエストに対して、サーバが開いているポートを返信する

#### パッシブなftpの構築
- XXX~XXXポートが開いていると教える
- proftpd.conf
  - `PassivePorts {port} {port}`
- vsftpd.conf
  - `pasv_enable=YES`
- pure-ftpd.conf
  - `PassivePortRange {port} {port}`

#### Anonymousのよくある対処
- <Limit ~ftp>など、匿名ユーザ用のディレクトリを作る

## OpenSSH

- PermitRootLogin

- MaxAuthTries...認証の試行回数
- RSAAuthentication...SSH1公開鍵認証

- PubkeyAuthentication...SSH2公開鍵認証
- AuthorizedKeyFile...公開鍵の場所
- PasswordAuthentication
- PermitEmptypasswords
- ChallengeResponseAuthentication...QA型の認証
  - 暗号プロセスのチャレンジのことでは無いので注意
- usePAM...PAMを使用する
  - 無くても直接passwdを見に行ける機能はある
- X11Forwarding
- AllowUsers
- DenyUsers
- AllowUsers
- DenyUsers
- AllowGrup
- DenyGroup
- Subsystem...外部サブシステムを指定
  - sftpなど

### サーバ認証sshで使用する鍵あれこれ
- この鍵は分配しない。サーバ自身の検証に使用する
- ここには鍵が1つだけ入っている
- ssh_host_key(.pub)
  - 秘密鍵(SSHバージョン1と認識)
- ssh_host_dsa_key(.pub)
  - das秘密鍵(SSHバージョン2と認識)
- ssh_host_rsa_key(.pub)
  - rsa秘密鍵(SSHバージョン2)
- ssh_host_ecdsa_key(.pub)
  - ecdsa秘密鍵(SSHバージョン2)
- ssh_host_ed25519_key(.pub)
### サーバ側の ~/.ssh/known_hosts
- ホストの正当性を証明するもの
- 接続元、鍵の種類、公開鍵が保存されている

### ログインしてきたユーザを検証するフィンガープリント
- 目視での検証ぐらいにしか使わない
- `ssh-keygen -l -f /etc/ssh/ssh_host_rsa_key.pub`

### ssh-keygenコマンド
- ssh-keygen
  - -f ...鍵ファイル名を指定
  - -t ...暗号化方式を指定
    - -t rsa1
    - -t dsa
    - -t rsa
    - -t ecdsa
    - -t ed25519
  - -p...既存の鍵のパスフレーズを変更
    - -fで既存ファイルを指定して使う
    - 対話型のフォーマットが開く
  - -P {phrase}...古いパスフレーズを指定する
  - -N {phrase}...新しいパスフレーズを指定
  - -l ...フィンガープリントを表示
  - -R {host} ...known_hostsから削除する

### ssh-keygenコマンドで作成される鍵
- idenity(.pub)
  - v1の旧式
- id_dsa(.pub)
- id_rsa(.pub)
- id_ecdsa(.pub)
- id_ed25519(.pub)

### sshでクライアント認証するために必要なこと
- 公開鍵をサーバに共有しておく
- この時の保存先は/.ssh/authorized_key

### ssh-agent

#### 【復習】 TCPフラグ
- 3way hand shakeで使う
  - SYN...通信の開始
  - ACK...受領確認
  - FIN..データの受信完了
- 通信開始
  - 1. SYN
  - 2. SYN + ACK
  - 3. ACK
- 通信終了
  - 1. FIN
  - 2. ACK
  - 3. FIN
  - 4. ACK

## openVPN
- VPN
  - IP-TCP間のカプセル化を実行
- PKI(Private Key Infrastructure)を使用する
- セキュアな証明書の検証機能
  - クライアント側に以下を配置
  - opnevpnサーバ側に以下を配置
    - CA証明書、サーバ証明書、サーバ秘密鍵、DHパラメータ
  - opnevpnクライアントに以下を配置
    - CA証明書、クライアント証明書、クライアント秘密鍵
  - 自己証明書も利用可能

### OpneVPNの接続方法
- ルーティング接続
  - 仮想トンネルを使用して接続する
  - L3で動作
  - IPアドレスを転送する
- ブリッジ接続
  - 仮想IF経由で接続する
  - L2で動作
  - MACアドレスを割り当てる

### 必要なファイルを一括設定する
- サーバ証明書のCA証明書の設定を一括で管理する
- `/etc/openvpn/vars`
  - export KEY_COUNTRY = "JP"
  - export KEY_PROVINCE="TOKYO"
  - ...など
  - ただの設定コマンドが書いているだけ
  - 実行はsource /etc/openvpn/varsを実行

### CA証明書、CA秘密鍵の作成
- `etc/openvpn/build-key-server server`
- 引数にホスト名とファイル名を指定
- 出力に`server.crt`、`server.key`が作成
- これらは`etc/openvpn/keys`に配置

### DHパラメータ作成
- `etc/openvpn/build-dh`
- `dh1024.pem`もしくは`dh2024pem`が作成
- これも`/etc/openvpn/keys`に配置

### クライアント証明書の作成
- `./build-key client`
- `client.scr`,`client.key`を作成
- これも
- `/etc/openvpn/keys`に配置

### 起動スクリプト
- `/usr/share/doc/openvpn/examples/sample-config-files/`にサンプルがある
- 基本はコピーして編集して使う
- 一般に起動スクリプトは`/etc/openvpn/`配下に置く
- 主要な起動スクリプト
  - `openvpn-startup`
  - `openvpn-shutdown`

### 設定ファイル
- `/etc/openvpn/server.conf`
- `/etc/openvpn/client.conf`

### opneVPN設定ファイル
- `/etc/openvpn/server.conf`
  - dev [tun|tap] ... IPルーティング方式|Ethernet bridge方式
  - proto [tcp|upd]...udpが推奨
  - port XXX ...待ち受けるポート番号
  - server {addr} {mask} ...割り当て可能範囲の指定
  - push "{}" ... サーバから特定のクライアントへのルーティングやDNSの設定を送信
  - ifconfig-pool-persist {file} ...クライアントのIPを記憶して固定割り当てする
  - cient-to-client...VPNに接続しているクライアント通信を許可
- `/etc/openvpn/client.conf`
  - remote {host or ip} {port}
  - nobind ...動的ポートを使用する
- 鍵関連。これはそれぞれ必要なサーバに保存
  - ca {caルート証明書}
  - cert {公開鍵証明書}
  - key {秘密鍵}
  - dh {鍵ファイル} 署名用なので、サーバ側のみ指定



### VPNの相互認証プロセス
- サーバ、クライアントの双方がcertを交換
- certを使用して、caに正規なものか問い合わせ
- keyを使用して、ユーザを認証
- dhを使用して、ストリーム暗号化開始
