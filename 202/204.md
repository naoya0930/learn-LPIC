# DHCP
- Dynamic Host Configration Protocolの略
- IPを貸し出すことをリースという

#### DHCP接続までの流れ
- 1. DHCP Discover 
  - クライアントブロードキャスト
  - 255.255.255.255のUDP
- 2. DHCP Offer
  - DHCPサーバからのIP提案
- 3. DHCP Request
  - DHCPの受諾申請
- 4. DHCP Ack
  - DHCP承諾メッセージ

#### DHCPサーバができるサービス
- ISCDHCP
  - Internet Software COnsotium
  - `dhcpd`デーモンを起動

#### DHCPクライアントができるサービス
- dhclient
- pump
- dhcpcd


#### dhcpdの設定ファイル dhcpd.conf
- `/etc/dhcpd.conf`など
- subnet [ip] netmask [mask] {ここに設定を記述}
- サブネットごとの設定になる

#### 主要な設定項目
- `option domain-name`...ドメイン名
- `option donmain-name-server`　...DNSサーバのIP
- `option routers` ...デフォルトゲートウェイIP
- `option subnet-mask` ...サブネットマスク
- `option broadcas-address`...ブロードキャストアドレス
- `option ntp-servers`...NTPのIPアドレス
- `option nis-domain`...NISサーバのドメイン
- `optin nis-servers`...NISサーバのIP
- `option netbios-name-servers`...WINSサーバのIPアドレス
- `deafault-lease-time`...IPリース期間(秒)
  - クライアント側の要求時間が優先される
- `max-lease-time`...クライアントがリース時間を求めた場合の許可最大リース時間
- `rage [dynamic-bootp]`...クライアントに割り当てるIP
- `host{}`...ホスト名で固定IPを使用。以下はそのホストに対する設定
  - `fixed-address`...そのクライアントに割り当てたIP
  - `hardware`...クライアントを特定するためのMAC

#### リースしている状態の保管
- `/var/lib/dhcp/dhcp.lease`に保存している
- 仮想ファイルではない
- IP貸し出しに関する情報を提示する

```
# リース情報1（現在アクティブな貸し出し）
lease 192.168.1.100 {
  starts 1 2026/05/10 06:00:00;       # 貸出開始（曜日は 1=月曜...7=日曜）
  ends 1 2026/05/10 12:00:00;         # 貸出終了
  tstp 1 2026/05/10 12:00:00;         # サーバー間同期用タイムスタンプ
  cltt 1 2026/05/10 06:00:00;         # クライアントが最後に送ってきた時刻
  binding state active;               # 現在「貸し出し中」
  next binding state free;            # 期限が切れたら「空き」にする予約
  rewind binding state free;
  hardware ethernet 00:0c:29:ab:cd:ef; # PCのMACアドレス
  uid "\001\000\014\051\253\315\016"; # クライアント識別子
  client-hostname "engineer-pc-01";    # PCのホスト名
}
```
#### DHCPを利用できるようにする
- REDHAT系
  - `/etc/syconfig/network-script/ifcfg-eth0`に以下を記載
  - `BOOTPROTO = DHCP`
- DEBIAN系
  - /etc/network/interface
  - iface eth0 inet dhcp
  - 現在はnetplanアーキテクトに変わっため、/interface が無い


#### DHCPリレーエージェント
- DHCP Discoverがルータを通れないため中継として動作
- LAN内で発せられたブロードキャストのIPをDHCPサーバに書き換えて転送
- 主にサービス`dhcrelay`が使用される
  - キャッシュ機能は持っていない。中継するだけ
- `dhcrelay -i eth1 172.17.0.2`
  - eth1に来たブロードキャストを172.17.02に転送

#### IPv6設定
- DHCPサーバは利用しない
  - IPv6では基本的にルータでIPを分配する
- 十分に長いアドレスのため、MACアドレスを識別子として使える
- ルータ
  - SLAAC
    - ネットワーク部と自身のMACアドレスから自身が勝手に決める
  - ステートフルDHCP
    - ルータが分配する
  - ステートレスDHCP
    - IPはSLAAC方式で自身で決める。
    - DNSなどはDHCPから取得

# PAM
- Pluggable Authentication Module
- プログラムに対するユーザ認証用の共有ライブラリ
- `/etc/passwd`,`/etc/shadow`やldapも利用可能
  - 共有ライブラリファイルとして置かれている
- `/etc/pamd.d`にPAMを使用するプログラムの一覧が見える
  - これらは実際のコマンド/バイナリ側から参照される
  - いつ呼ぶのかは定義しない
- 基本は以下のような書式
  - [認証方法] [コントロール] [共有ライブラリ(認証)]
- サンプル

```/etc/pam.d/sshd
# 1. 認証 (auth)
# 連続失敗したアカウントをロックするかチェック
auth       required     pam_faillock.so preauth silent deny=3 unlock_time=600
# 標準的なパスワード認証（/etc/shadow等を確認）
auth       include      system-auth
# 2. アカウント管理 (account)
# パスワード期限切れやアクセス禁止時間帯をチェック
account    required     pam_nologin.so
account    include      system-auth

# 3. セッション管理 (session)
# ログイン時に環境変数やリソース制限(ulimit)を適用
session    required     pam_selinux.so close
session    required     pam_loginuid.so
session    include      system-auth

```


#### PAMのモジュールタイプ
- 認証方法
  - auth ... パスワードを使ったユーザ認証を実行
  - account ... ユーザ認証が可能か？パスワードが有効期限切れでないか？
  - password ... パスワードの設定と変更
  - session ... ユーザ認証の前後に実行すべき処理。マウント、ロギングなど
- コントロール...認証OK時、NG時の次の挙動を定義
  - requisite
    - OK時...次の行へ
    - NG時...他の認証を実行せず、その場の結果をNGとする
  - required 
    - OK時...次の行へ
    - NG時...他の認証も実行するが、結果はNGとする
  - sufficient
    - OK時...requiredが失敗していなければその場で全体でOK判定
    - NG時...全体の判定には影響しない
  - optional
    - OK時...次の行へ
    - NG時...次の行へ
- PAMに外部ファイルを作用させる
  - include
    - 他のPAMファイルを展開する。
    - 呼び出したい処理を部分的に指定して使う
    - 展開先でsufficientでOKが出れば全体でOKとする
      - `auth include XXX`
      - `session include XXX`
  - substack
    - 外部の判定に委ねる。
    - OK,NGを戻り値としてもらうイメージ
    - `auth sufficient substack XXX`
    - `auth substack XXX`
      - 何も書かずにsubstackを呼び出した場合は、requiredとして扱う

#### PAMモジュール
- 主にauthで使うモジュール
  - pam_unix.so .../etc/shadowを参照する
  - pam_rootok.so ... それ以上チェックせず、ルートユーザのログインを許可
  - pam_wheel.so...wheelグループ(特権グループ)に属しているか確認
  - pam_listfile.so ...ファイルの内容に基づいてサービスを許可/拒否
  - pam_securetty.so.../etc/securettyファイルに記載された端末のみrootログインを許可。
    - 端末とはcosoleやtty1のこと
  - pam_nologin.so ... /etc/nologinファイルがあれば一般ユーザのログインを拒否
- 主にaccountで使うモジュール
  - pam_unix.so ...パスワードの有効期限を確認
  - pam_time.so.../etc/security/time.confを参照してログイン可能な時間帯を制限
  - pam_succeed_if.so...UIDなどの条件に基づいた許可/拒否
- 主にpasswordで使うモジュール
  - pam_unix.so ...パスワードを変更する
  - pam_cracklib.so ...パスワードの安全性向上
  - pam_pwdb.so ... ユーザ認証とパスワード変更を実施(古い)
- 主にsessionで使うモジュール
  - pam_env.so ... ログイン時の環境変数の初期化
  - pam_unix.so...ログインしたことをログに書き出す。
  - pam_limits.so ...ユーザの使用できるリソースを制限
    - プロセス数、ファイル数、メモリ使用数などを制限できる
- 補助的にどこでも使うモジュール
  - pam_deny.so ...認証に対し、常に失敗を繰り返す
  - pam_stack.so ...他のPAM呼び出す(include,substackで使用する)
  - pam_warn.so...認証をsyslogに記録して管理者に警告

# LDAP
- Lightweight Directory Access Protocol
- DITという構造で利用者を管理する
  - Directory Information tree
  - ディレクトリ情報ツリー
  - エントリは識別名とその値から構成される
    - `uid :XXX`
    - `ou : DDD`
    - `dc : jp` など
    - このkey-valueをDN(Distiguished Name),DN値とか呼ぶ

#### LDAPのサーバ
- 手軽に実現するには主に`slapd`サービスを使う
- Stand-alone LDAP Daemonの略。
- OpenLDAPのデーモン名
- TCP/UDPの389番を使用する
#### DNの表現 LDIF
- LDAP Data Interchange Formatと呼ぶ
  - DNを表現する上で、コロン「:」で挟み、改行で情報を列挙する
  - `.ldif`ファイルにする

#### スキーマとは(出ないが調査した)
- オブジェクトクラスや属性の定義のこと
- LDAPサーバにおけるデータの設計図
  - Attribute Type(属性型)
    - 項目名
    - データ型
  - Object Class(オブジェクトクラス)
    - Must(必須) or May(任意)
  - Syntax
    - 書式ルール
### 主要なスキーマファイル
- ISOやRFCで定義されたものがほとんど
  - core.schema
    - OpenLDAPで必須
  - cosine.schema
    - X.500で規定されたディレクトリサービスに関するスキーマ
  - inetorgperson.schema
    - アドレス帳などの個人情報を扱う
    - ホワイトページはこれに沿う
  - nis.chema
    - UNIX/Linuxのユーザがグループを扱う

### schemaファイルのオブジェクト識別子
- オブジェクトクラス、属性にOID(Object ID)をつけている
  - IANA(Internet Assigned Numbers Authority)が管理
  - IPとか主要ポートとか見てる団体

### ホワイトページ
- 個人別連絡帳のこと
- intorgperson.schemaに沿うことが多い
- 属性
  - cn...一般名 common name
  - sn ...苗字 surname
  - mail .... メールアドrす
  - o ...組織名 organization name
  - ou  ... 組織単位名 organizational unit
  - streetAdress 住所
  - postCode ...郵便番号
  - telephonNumber ...電話番号
  - description ...説明

### slapd 設定ファイル
- /etc/openldap/slapd.conf
  - （現在はこのディレクトリは作成されない）

### slapd.conf
- include {/schema}...スキーマファイルの読み込み
- database...ディレクトリデータを格納するデータベース形式
- sufix...管理するディレクトリのトップエントリ
- rootdn...ディレクトリ管理者のDN
- rootpw ...管理者のパスワード
- directory...LDAPのDBのディレクトリ
- index　{name} {type}...検索用インデックスを設定

#### slapd.conf内でのOpenLDAPに対するアクセス制御
- slapd.conf内で書く
- `access to {対象エンティティ} by {接続元} {アクセスレベル}`
  - ここに書かれていない設定はすべてのユーザがアクセス可能
  - ただしエントリの更新はrootdnだけが可能
- 対象エンティティ
  - `*` ...すべてのエントリ
  - `attr =` ...指定した属性のみ
  - `dn =`...指定したDNのみ
- 接続元
  - `*`
  - `anonymous` ...認証前のユーザ
  - `users` ...認証されたユーザ
  - `self`　...接続中の認証済みユーザ自身
  - `dn=`
- アクセスレベル
  - write
  - read ...検索結果を参照できる
  - search ...検索できる
  - compare ...比較できる
  - auth ...認証を受けることができる
  - none ...アクセス不可

### クライアントが実行するコマンド
- `-D`で実行者のDNを指定する
  - CLI形式のクライアントインターフェイスを持たない
- `ldapapadd` ... エントリの追加
- `ldapsearch` ...エントリの検索
- `ldapdelete`...エントリの削除
- `ldapmodify`...エントリの変更
- `ldappasswd`...パスワードの変更。
  - ここではuserPasswordという属性の変更
  - スキーマの定義でldap上ではハッシュ化されて保存されている

#### エントリの追加
- ldapadd -h {host} ...LDAPサーバの指定
- ldapadd -x ...SASLを使用せずに簡易認証する
- ldapadd -D {DN} ...認証に利用するDNを指定
- ldapadd -W ...認証時のパスワードを対話的に入力
- ldapadd -w {pass} ...認証時にパスワードを指定
- ldapadd -f {file_name} ...LDIFファイルを指定
- SASLプロトコル
  - Simple Authentication and Security Layer
  - 認証を本体から切り離してセキュアな認証を共通化したもの
  - 別のライブラリ経由で認証を実行する
    - GSSAPI ...Kerberos認証を使う
    - DIGEST-MD5 ...チャレンジ・レスポンスを使う
    - EXTERNAL ...TLSやOSの権限を使う
    - PLAIN ...平文認証
####　エントリの検索 ldapsearch
- ldapsearch -D {DN} -w {pass} [query] ...基本的な検索
- ldapsearch -h {hostaname}...LDAPサーバの指定
- ldapsearch -x ...SASLを使用せずに簡易認証
- ldapsearch -b {DN}...ベースDNを指定する。検索はこの配下を実施
- ldapsearch -L ...検索結果をLDIF v1で表示
- ldapsearch -LL ... 検索結果をコメントなしで表示
- ldapsearch -LLL ...検索結果をコメントとバージョン情報なしで表示
- 正規表現にはポーラン記法が使用可能

### LDAPなどの通信をキャッシュする sssd
- クライアントが自身が起動するデーモン
- System Security Service Daemon
- LDAPサーバに聞きに行ったりしてくれる
- 使用する場合、nsswitch.confに以下を記載

```/etc/nsswitch.conf
#### sssが問い合わせに行ってくれるため、LDAPは書かない
passwd:     files sss
group:      files sss
shadow:     files sss
services:   files sss
netgroup:   files sss
```

- 設定ファイルは`/etc/sssd/sssd.conf`

#### SSSDの設定ファイル `/etc/sssd/sssd.conf`
- sambaっぽい書式

```

[sssd]
# SSSDが提供するサービス（NSS:名前解決、PAM:認証）
services = nss, pam
# 下記で定義する[domain/...]のセクション名と一致させる
domains = LDAP_DOMAIN
# ログの出力レベル（0-9, 0は致命的エラーのみ、高いほど詳細）
config_file_version = 2

[nss]
# ユーザー情報が見つからない場合のネガティブキャッシュ時間（秒）
filter_users = root,bin,daemon,sys,adm,lightdm

[pam]

[domain/LDAP_DOMAIN]
# --- 接続先の設定 ---
# id_providerをldapにすることでLDAPサーバーを見に行く
id_provider = ldap
auth_provider = ldap
# LDAPサーバーのURI（複数指定時はスペース区切り）
ldap_uri = ldap://ldap.example.com
# 検索の起点となるBase DN
ldap_search_base = dc=example,dc=com

# --- 認証の設定 ---
# 簡易認証（Simple Bind）を使用する場合の設定
# 一般的なユーザー属性のマッピング
ldap_schema = rfc2307bis
# TLS/SSLを使用する場合（推奨）
# ldap_id_use_starttls = true
# ldap_tls_cacertdir = /etc/openldap/cacerts

# --- キャッシュ（オフラインログイン）の設定 ---
# これが「キャッシュDNS」のように機能する肝の設定
cache_credentials = true
# オフライン時にキャッシュを保持する期間
account_cache_expiration = 7
# 資格情報のキャッシュ保持期間
entry_cache_timeout = 5400

# --- ユーザー属性の設定（環境に合わせて調整） ---
# LDAP上のどの属性をLinuxのシェルやホームディレクトリに割り当てるか
ldap_user_search_base = ou=Users,dc=example,dc=com
ldap_group_search_base = ou=Groups,dc=example,dc=com
# デフォルトのシェル（LDAP側に属性がない場合の予備）
default_shell = /bin/bash
# ホームディレクトリの自動生成パターン
fallback_homedir = /home/%u

```
