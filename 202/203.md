# ファイル共有サーバ

### Windows基礎知識
#### サーバ群構成

#### ワークグループ構成
- 管理用のサーバをもたず、各サーバが独立して存在
- 特定のサーバがマスターブラウザとして稼働する
- 管理認証権があるわけではない

#### 認証って何?
- ここではドメイン認証を通して、ユーザセッションを作成するまでの流れ。
- ゴールはユーザシェルを起動するところまで
- 手続き
  - Winlogon
  - LSASS
  - ドメインコントローラ探索
  - 認証成功
  - ユーザシェル起動
- サーバ群で管理する場合、LSASSアクセストークンによって認証・認可を管理している
- トークンに含まれるのもの
  - ユーザSID
  - 所属グループSID
  - 特権
  - 制約
#### ドメインコントローラって何？
- アカウント管理(AD,BDC)を動かすソフトウェアのこと

#### NTドメイン構成
- Windows端末の集中管理を実施
- Windows NT, 9X, 2000以前の構成
- NTLM(NT LAN Manager)というチャレンジ・レスポンス方式で実施
  - LDAP,Kerberosに非対応だった
- 管理系統は以下
  - PDC(Primary Domain Controller)
    - ユーザ作成・削除・パスワード変更
    - 唯一の書き込み可能ノード
  - BDC(Backup Domain Controller)
    - PDCのレプリケーション
    - 認証要求を処理
    - SAMは読み取り専用
    - PDC障害時に昇格可能
  - 他PC
- 認証周りの語句も結構違う
  - NTLM...認証方式。Kerberosではない
  - NetBIOS/WINS...名前解決で使用する方式、ADではDNS
- NetBIOS
  - Network Basic Input/Output System
  - 名前解決と通信の論理インタフェース
  - コンピュータ名を使用する
  - IPアドレスを使用しない
    - ☆ ルータを超えられない領域でしか動作しない
  - ブロードキャストを多用する
  - LANに同じ名前のコンピュータ名が存在すると破綻する
    - そのため、通常は同じ名前コンピュータのネットワークの参加を拒否する
- WINS
  - Windows Internet Name Server
  - NetBIOS名とIPアドレスを集中管理する
  - DNSのようなホスト名ではなく、コンピュータ名で管理している
- LMHOSTSファイル
  - WINSが存在しない場合にNetBIOS名とIPの表を保持する
  - 基本はブロードキャストで探すため、実用では使わない
- NBT
  - NetBios over TCP/IP

#### AD構成
- Active Directory構成
- ドメインコントローラ(DC)
  - ADを提供するサーバを保有
- ドメインに所属する形でPCが存在
  - DCはレプリケーション構成を想定している
- 特徴
  - ユーザ認証にKerberosを使用する
  - グループ管理、グループポリシーが使用可能
  - 組織に階層(OU)を持たせることができる
- DNSを利用したディレクトリ管理

#### ADとDNS
- ADはDNSなしでは機能しない
- DNSのSRVレコードによって連携している
  - `_service._protocol.name TTL IN SRV priority weight port target`
  - `_ldap._tcp.example.local. 600 IN SRV 0 100 389 dc01.example.local.`
  - `_kerberos._tcp.example.local. 600 IN SRV 0 100 88 dc01.example.local.`
    - _service...提供サービス名
    - _protocol...通信プロトコル(tcp/udp)
    - name...ドメイン名
    - priority...優先度（小さいほど優位）
    - weight...同優先度内の重み
    - port...サービスポート
    - target...サーバのFQDN

#### Kerberosチケット/アクセストークン
- Kerberosは認証の証明書
  - AD/DCが発行する。
  - 有効期限の制限がある
- アクセストークンは認可の実態
  - クライアントOSによって発行される

## Samba
- WindowsのNW構成を利用してLinuxでも扱えるようにしたもの
  - 実態はソフトウェア群
- Windows、Linux混成の設定共有ができるようになった
- SMB(Server Message Block)プロトコルによって、以下ができる
  - ファイル共有
  - プリンタ共有
- NetBIOSによって駆動している
  - NetBIOS over TCP/IP の139番
- SMBの拡張であるCIFS(Common Internet File System)も使用可能
  - 445/tcpを使用する
  - Direct Hosting of SMBとも呼ばれる

#### SID,UID
- SID ... Security ID
  - ADがユーザ、グループを識別するための固有識別子
  - S-X-X-XX-XXXX-XXXX-XXXX-XXXX
  - 末尾の4桁はRID(Relative ID)と呼ばれ、ドメイン内での個人番号を表す
- UID ... User ID
  - Linuxが管理するユーザID
  - rootが0でユーザは1000以降など

#### ファイル共有ソフトとしてのSamba
- 3層モデルでのアクセス管理を実施
  - 認証(ADに含まれている誰なのか？)
  - 共有レベル制御(smb.confによる制限)
  - ファイルシステム制御
- Sambaにおける共有名の解決
  - \\server\{sharename}にアクセスしたとすると、、、
    - smb.confの[{sharename}]を探す
    - 見つからなければ、[homes]を参照する
      - ADにユーザ存在し、認証が有効で、Linux側でUID/GIDに解決できればOK
      - さらにディレクトリが存在することが条件(設定で自動作成もできる)
  - [homes]の暗黙ルール
    - pathパラメータを設定できない(/home/{username})の設定だから
    - valid users =%s ... 他のユーザはログインできない
- [homes]以外のアクセス可否は以下で判断
  - valid users
  - invalid users
  - read list
  - write list
- ファイル単位の制御
  - SIDからUIDに変換してLinuxカーネルレベルで制限
#### Sambaのプロセス
- smbd...ファイル共有、プリンタ共有。
  - 445/tcp, 139/tcpを使用する
- nmbd...NetBIOSのネームサービス機能
  - 各端末の名前とIPを変換している(DNSみたいな感じだが、DNSではない)
  - 137/udp、138/udp

#### Samba設定ファイル
- smb.conf
- ドメインサーバとしてのSmamba(AD連携ファイルサーバ)
```
[global]
    workgroup = EXAMPLE
    realm = EXAMPLE.COM
    security = ADS

    # Kerberos
    kerberos method = secrets and keytab

    # Winbind（SID ↔ UID 変換）
    winbind use default domain = yes
    winbind enum users = no
    winbind enum groups = no
    winbind refresh tickets = yes

    idmap config * : backend = tdb
    idmap config * : range = 3000-7999

    idmap config EXAMPLE : backend = rid
    idmap config EXAMPLE : range = 10000-999999

    # ACL / 拡張属性
    vfs objects = acl_xattr
    map acl inherit = yes
    store dos attributes = yes

    # ログ
    log file = /var/log/samba/log.%m
    max log size = 1000
    logging = file

    # プロトコル制御
    server min protocol = SMB2
    server max protocol = SMB3

    # パフォーマンス
    socket options = TCP_NODELAY
    aio read size = 1
    aio write size = 1

[share]
    comment = AD Integrated File Share
    path = /srv/samba/share
    browseable = yes
    writable = yes

    # AD ユーザのみ許可
    valid users = @"EXAMPLE\Domain Users"

    # ACL を Windows 側で管理
    inherit permissions = yes
    inherit acls = yes
```

#### Sambaのセクション
- 予約語が存在する。任意の名前でセクションを作成できる。
  - [global]
    - サーバ全体のパラメータを定義
    - ここを変更したらSambaを再起動しないと反映されない
  - [homes]
    - ユーザのホームディレクトリの共有に関するパラメータを設定する
  - [printers]
    - プリンタの共有に関する設定
    - プリンタ一覧に表示される
    - pathにはジョブ一覧(spool)の場所を指定する
    - `printable = yes`の指定が必要
  - [print$]
    - プリンタドライバの配置場所
    - pathで指定する

  - [{any}$]
    - 直接アクセスのみで閲覧可能
    - 共有名の末尾ドルを隠すのは、windows側の仕様
    - sambaは特に特別扱いしない
  - [その他任意の名前]
    - 共有名とか呼ばれる
 
#### smb.conf, [global]セクションでの制御

#### smb.conf, [global]セクションで使うパラメータ
- 基本動作・識別
 - `workgroup =` ...ワークグループ名、もしくはドメイン名
 - `server string =`...windowsネットワーク上で表示される説明文

- 認証、セキュリティ

 - `realm =` ...ADのrealm名、通常はドメイン名
 - `kerberos method =secrets and keytab`...Kerberos認証の方式
 - `hosts allow =`...接続を許可するホスト、IP
 - `guest account =`...アカウントが存在しないユーザのユーザ名の設定
 - `map to guest =`...存在しないゲストをどう扱うか
   - Never...ゲストログインを拒否
   - Bad User...存在しないユーザをゲストとしてログイン
   - Bad Password...パスワード入力のミスでもゲストユーザとしてログイン
 - `password server =`...パスワードサーバ(DC)の設定
- winbind/IDマッピング
 - winbind系
   - `winbind use default domain =`
   - `winbind enum users =`
   - `winbind refresh =`
 - imap系
   - `imap config * : backend =` ...
- プロトコル制御
 - `server min protocol = SMB2_10`
 - `server max protocol = SMB3`
- log
 - `log file =`...ログファイルの出力先
 - `max log size =`...ログファイル最大サイズ

- パフォーマンス
- `socket options =TCP_NODELAY`...ソケットオプション
- `aio read size =`...何バイト以上で非同期通信を開始するか？

#### 共有セクションで使用するパラメータ
- 共有の基本属性
  - `path =` ... 実際のLinux側のディレクトリ
  - `comment =` ...windows エクスプローラで見れる共有の説明文
  - `browseable =yes|no` ...ネットワーク一覧(ブラウンジング)に表示するか？
    - noでも直接指定すればアクセス可能
  - `writable = yes|no`
  - `read only = yes|no`
  - `guest ok = yes|no`...認証なしのアクセスを許可するか？
- アクセス制御
  - `valid users = ` ...アクセスを許可するユーザ/グループ
  - `invalid users =` ...明示的な拒否、valid usersより優先
  - `read list =` ...読み取り専用ユーザ
  - `write list =` ...書き込み可能ユーザ。writableやreadonlyより優先
- 権限・所有者の制限
  - `create mask =` ...ファイル作成時の最大パーミッション
    - umask形式ではなく、これ以上の権限でファイルは作成できないという意味
  - `directory mask = 2775` ...ディレクトリ作成時のパーミッション
    - 2で始まるのは、SGID(グループ設定を継承する)
  - `force create mode`...かならず最低限付与するパーミッション 
  - `force user =`...全操作を特定ユーザとして実行
  - `force group =`...全操作を特定グループとして実行
- ACL
  - `inherit permissions = yes|no` ...親ディレクトリのPOSIX顕現を継承
  - `inherit acls =yes|no` ... Windows ACLを継承
  - `map acl inherit =yes|no` ...windows ACLを再現する
  - `store dos attributes =yes|no`...読み取り専用、隠し属性を保存
- VFS(拡張機能)
  - `vfs objects =` ...ファイルシステムの拡張昨日のロード
    - acl_xattr ...aclの保存
    - recycle...ゴミ箱
    - full_audit...監査機能
- ファイル表示制御
  - `veto files =`...特定ファイルの非表示、作成不可
  - `hide files =`...指定したファイル、ディレクトリを非表示にする。アクセスは可

#### アクセス権はpathごとに決まるの？
- Sambaでの[homes]他の共有設定ではYES
- その他の設定では、`write list =user @group`などで制御可能。
  - ファイルごと、ディレクトリごとの設定はLinuカーネル側で設定する
- 設定はLinuxカーネルのファイルシステム側が優先される

#### sambaアクセスの際の共有名の使いかた
- smb.confでは、`[共有名]`で定義する
- クライアントからは、 `\\サーバ名\共有名`でアクセス
- サーバ名はDNSで登録、共有名は、Samba側で解決する。
  - `\\サーバ名\ユーザ名`を利用すると、[homes]を使用する
  - `\\サーバ名\セクション名`を利用すると、[セクション名]を利用する

#### [global]sever roleパラメータ
- sambaがwindowsネットワーク内の何として振る舞うかを決める
- AUTO
  - securityパラメータの設定に従う
- STANDALONE
  - スタンドアローンのファイル共有サーバ
- MEMBER SERVER
  - ドメインメンバーのサーバとしてAD、ドメインに管理される
- CLASSIC PRIMARY DOMAIN CONTROLLERS
  - NTドメインのプライマリドメインコントローラ(PDC)
- CLASSIC BACKUP DOMAIN CONTROLLERS
  - NTドメインのバックアップドメインコントローラ(BDC)
- ACTIVE DIRECTORY DOMAIN CONTROLLER...ADのドメインコントローラ
  - ユーザ情報、グループ権限、グループ権限、DNS情報を引き受ける
#### [global]securityパラメータ
- `security = user`
  - ユーザ名とパスワードでローカル認証を行う設定
  - Samba内部のユーザ認証方式を使用する
  - Lunux(UID/GID)とWindows(SID)の変換はユーザ名で実施
  - パスワード認証方式は`passdb backend`に従う
    - TDB(Trivial DataBase)...バイナリ形式のファイルに保存
    - smbpasswd...テキスト形式のファイルに保存
- `security = share`
  - パスワードだけで認証を行う
  - 共有（share）ごとに違うパスワードを設定している
  - ユーザが特定できない
- `security = domain`
  - ドメインコントローラにより認証を実施
  - ここでいうドメインとはNTドメイン(NetBIOSドメイン)のこと
- `security = server`
  - 他のSMBサーバにより認証を実施。NT構成などで実施
  - NTと信頼した通信は実施しないため、注意。
- `security = ads`
  - ADドメインのDCによって認証を実施。Kerberos認証
- 上記に倣って、`passdb backend =`も変わる
  - `passdb backend = smbpasswd`
  - `passdb backend = tdbsam:/etc/samba/passdb.tdb`
  - `passdb backend = ldapsam:ldap://サーバ名:ポート番号`
  - 複数も設定できる
#### [global]パスワード認証に関わるパラメータ
- `smb passed file =`
  - smbpasswd形式のパスワードファイルの場所
- `unix password sync= Yes|No`
  - LinuxとSambaのパスワードを同期させるか
- `passwd program =`
  - パスワード変更時に実行するプログラム
- `passwd chat =`
  - パスワード変更時に応答するメッセージ

#### security = userで指定できるpassdb backend
- `passdb backend = tdbsam`...Samba内部DB(Trivial Database,KVS方式のDB)
- `passdb backend = smbpasswd`...テキストファイル形式。暗号化なし
- `passdb backend = ldapsam`...認証をLDAPサーバに移譲
- ※ sam...Security Account Managerのこと

#### Linuxにおけるユーザ管理、Sambaにおけるユーザ管理
- ファイルシステム上、LinuxユーザとSambaのユーザはマッピングされていなければならない
  - アクセス権にそって管理されるため 
- 以下のような基本ルールがある
  - Linuxでのユーザ名(useraddで追加したユーザ)と、Samba(pdbeditなどで追加したユーザ)に関してユーザ名が同じであれば同じユーザ
  - LDAPsamを使用する場合は、そのLDAPサーバの設定に準拠(nsswitchでの設定は必須)
  - ADを使用する場合は、Samba上にユーザを持たない
    - winbindによってwindows SIDをUID/GIDに動的に変換する
#### じゃあ変更同期ってどうなっているの？
- security =userに限った話をする
- 原則同期はしない
  - 下記の一連の手続きを実行することで可能
  - `unix password sync =yes` ...unixの変更をLinuxに反映するか？
  - `passwd sync =yes` ... パスワードの同期を実施するか？yesにしなければ上記が動作しない
  - `passwd program = /usr/bin/passwd %u`...パスワード変更コマンドの実行
  - `passwd chat = *New*password* %n\n *Retype*password* %n\n *success*` ...変更時の画面上の表示
  - 非推奨らしい


#### LinuxとMS Windowsのユーザマッピング username map
- 認証前にクライアントが名乗ったユーザ名をSamba内部で扱うUNIXユーザ名に変換する
- `security =user`の場合
  - ローカルUnixユーザとの対応づけ
- `security = domain`の場合
  - NTドメインユーザ名との変換
- `security = ADS`の場合
  - ADユーザ名と、Unixユーザ名の変換
- smb.confファイルでglobalに以下のパラメータを追加
  - `username map = /etc/samba/smbusers`
- 例えば以下のようなパラメータ
  - `root = administrator admin`
  - `nobody = guest pcguest smbguest`
- 仕様 
  - User1="ユーザ1"のような書式
  - 左辺がクライアントが名乗るユーザ名
  - 右辺がSamba上、Unixで使われるユーザ名
 - 左辺、右辺ともに複数ユーザを指定したり、正規表現で対応できる

## マスターブラウザの選定[global]
- マスターブラウザはワークグループ、ドメイン単位で存在
- 選定に対する要素
  - OSレベル
  - 役割
  - 起動時間
  - コンピュータ名
- sambaサーバもマスターブラウザになれる
- sambaサーバで実行する設定(smb.conf内)

## winbind
- windwos NTもしくは、Windows ADのアカウントをSambaアカウントとして使う
  - SIDとUIDの変換
  - `security =user`では必要ない
- `winbindd`というデーモンが立つ
- 設定方法
  - /etc/nsswitch.confに以下のwinbindを追加
    - passwd: files winbind
    - group: files winbind
    - これを設定すると、`getennt passwd`でAD/NTユーザが戻ってくる
- 変換の流れ
  - 1. ADユーザがSMB接続
  - 2. DC認証
  - 3. SambaがSIDを取得
  - 4. winbindに問い合わせ
  - 5. SambaにUID/GIDが返る
  - 6. smbdが`setuid(UID)`してFS操作
- 動作
  - Samba以外にも、Windows ADアカウント情報でLinuxにログインできる
  - 共有されるもの
    - ユーザ名...Windowsに同じ
    - パスワード...windowsに同じ
    - アカウント管理...ロック・期限・無効化されたなど
    - UID/GID...Linux側で管理される
- ※ 似たサービスにSSSDが存在する
- ※ winbindはLinuxがADを参照する方向の参照しかできない

#### winbindの管理コマンド
- `wbinfo`...winbinddが取得したユーザアカウントなどを表示する
#### winbindに必要なモジュール
- pam_winbind.so...winbinddが取得したユーザの認証を行うモジュール
- libnss_winbind.so...nsswitch.confによってwinbinddと連携するために必要なモジュール

## Kerberos認証
- チケットで本人性を認証する
  - クライアント...利用者(PC)
  - サービス...アクセス先(ファイルサーバ群)
  - KDC...認証局(ADのDCが担う)
- ログイン時にチケットを取得(TGT:Ticket Granting Service)
  - 1. ユーザがID/passを入力
  - 2. クライアントがKDCに要求
  - 3. KDCが認証後、TGT(Ticket Granting Ticket)を発行
  - 4. クライアントが保管
- サービス利用時にチケットを利用する
  - 1. クライアントがTGTをKDCに提示
  - 2. KDCがサービスチケットを発行
  - 3. クライアントサービスがサービスへ提示
  - 4. サービスが検証し、アクセス許可
- チケットに含まれるもの
  - クライアントID
  - サービスID
  - セッションキー
  - 有効期限
  - 暗号化情報
- 
- ※ 似たサービスにNTLM認証が存在する


## NFSサーバの構築
#### NFS
- Network File System
- 必要になる主要なサービス
  - portmap
    - RPC(Remote Procedure Call)をTCP/IPポート番号に変換
    - クライアントにも必要
  - nfsd
    - ファイルシステムのエクスポートとクライアント要求の処理
  - mountd
    - リモートファイルシステムのマウント/アンマウント
  - エクスポート
    - NFSサーバ側でディレクトリを公開する
#### RPC
- RPC(Remote Procedure Call)
  - リモートホストの機能を他のホストから使えるようにする
  - ポート番号の拡張のために使用しているイメージ
  - サーバ側の関数を呼び出し、結果を取得する流れ
  - プロトコルというよりも、仕組み、アーキテクチャを指す
- RPCなプロトコル
  - MS-RPC
  - gRPC
  - ONE RPC(SunRPC)
  - JSON-RPC
  - XML-RPC
- RPCの識別子
#### Sun RPC
- `/etc/rpc`を確認することでサービスに対するプロトコルが定義されている
  - 100000 portmap/rpcbind
    - RPC番号とポート番号を結びつける
    - この2つのポート番号は固定
      - TCP/111
  - 100003 nfs
    - ファイル共有
    - 近年ではrpcbindを使用せずに2049を固定とする流れ
  - 100005 mountd
    - NFSのマウント要求を処理

- サービスに対するプロシージャを割り当てて意図した処理を実行している。

#### RPCを使用しているサービスを知る rpcinfo
- どう再しているRPCサービスの一覧を表示
- `rpcinfo`
- `rpcinfo -p {hostname}`
  
### NFSの基本挙動
- 基本的にユーザを認証する機能は持たない
- クライアントが宣言してきたUIDを使う
  - この時にはnfsdのUIDを参照する
  - UID=0ではrootとして扱う
- 最近になってKerberos認証と連携ができるようになりつつある
- rootユーザの場合は匿名アカウント(nobodyなど)になる
### NFSサーバの設定
- nfsdの設定
- `/etc/exports`を参照数する
- 公開するディレクトリと、クライアントを定義

```/etc/exports例
/share {IP}/{ip_mask}({option})
/pub {正規表現ドメイン} ({option})
```

- option
  - ro...読み取り専用でエクスポート
  - rw...読み書き化でエクスポート
  - no_root_squash...rootでのアクセス時にroot権限で実行
  - root_squash...rootアクセス時に匿名アカウント権限を利用
  - all_squash...すべてのアクセスを匿名アカウント権限で実行


#### 現在のexportsの状態を確認する exportfs
- nfsdはメモリ上で共有を管理している
  - /ext/exportsを再参照させる更新が必要
- `exportfs {option} {host:pass}`
  - export ...そのディレクトリをエクスポート
  - exportfs -a...すべてのディレクトリをエクスポート
  - exportfs -r...すべてのディレクトリを再エクスポート
  - exportfs -u...アンエクスポート
  - exportfs -v...詳細を表示
#### 現在のexportsでの状態を確認する showmount
- NFSサーバ上で実行
  - クライアントがマウントしているかが分かる
- クライアントからNFSサーバ宛に実行
  - 公開しているディレクトリを表示
- `showmount [host]`
- `showmount -a [host]`
  - クライアントのホスト名とマウントしているディレクトリを表示
- `showmount -e [host]`
  - 指定したホストでエクスポートしているディレクトリを表示

#### NFSの統計 nfsstat
- nfsstat
- nfsstat -s ...サーバ側の統計のみを表示
- nfsstat -c ...クライアント側のみの統計を表示
- nfsstat -n ... RPCの統計を表示しない。NFSのみ
- nfsstat -r ... NFSの統計を表示しない。RPCのみ
- nfsstat -o net ....ネットワーク層の統計を表示

#### NFSをマウントする
- `mount -t nfs {servername}:/{sever_mount_point} {client_mountpoint}`
  - -t nfsというマウントタイプが用意されている
- nfsをマウントする時のみ使用できるオプションがある
  - `mount -o bg -t nfs ...`...マウントに失敗してもバックグラウンドで試行する
  - `mount -o fg -t nfs ...`...フォアグラウンドでマウント
  - `mount -o soft -t nfs ...`...ソフトマウント
  - `mount -o hard -t nfs ...`...ハードマウント
  - `mount -o intr -t nfs ...`...ハードマウント時の割り込み許可
  - `mount -o retrans -t nfs ...`...ソフトマウントの再試行回数
  - `mount -o nolock -t nfs ...`...ファイルロックを実施しない
  - `mount -o rsize={bite}, wsize={bite} -t nfs...`...読み取り/書き込みブロックサイズ

#### ソフトマウント、ハードマウント
- ソフトマウント...ハングアップ時にタイムアウトする
- ハードマウント...応答があるまで要求を再試行
#### NFS vs iSCSI
- iSCSIはブロックデバイスとして認識
  - 新しいドライブとして認識する
  - ハードディスクの操作(SCSIコマンド)をTCP/IPで包む
  - 基本的に同時クライアントから作業は不可
- NFSはファイルストレージとして認識される
  - パーティションなどは実行できない
